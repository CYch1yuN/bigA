# Gate 1 数据层审核

结论：`FAIL`

审核基线：当前未提交工作树（`master` 尚无首次提交）。

## 复核结果

- `.venv` 使用 Python 3.11.9，`pytest tests -q` 实测 59 passed。
- 覆盖率实测 85%，但数据源适配器仅 AKShare 66%、BaoStock 47%。
- 未发现真实密钥、`.env`、PEM/KEY、DuckDB 或工作区内已跟踪的完整行情文件。
- Git 可用；Trae 所述“未安装 Git”不属实。当前问题是仓库尚无首次提交和远程地址。

## 阻断问题

### G1-01 必需数值缺失可静默通过质量检查

前复权数据按日期合并后可能出现 `NaN`；网络源完全缺少前复权结果时，提供器又会直接用未复权价格填充。当前质量检查既不检查必需列的空值/无穷值，也无法区分真实未复权数据与伪造的复权数据。因此缺失复权行情可能得到退出码 0，并污染后续信号。

修复要求：

- 禁止用 raw OHLC 静默回填 qfq OHLC。
- 增加必需字段完整性与有限数检查，raw/qfq OHLC、成交量、成交额、复权因子缺失或非有限值必须为 critical。
- 对 raw 与 qfq 日期集合不一致生成明确 critical，并加入 AKShare、BaoStock 两组离线测试。

### G1-02 AKShare ST 列名映射错误且失败后默认“非 ST”

适配器只在 ST 接口含英文 `code` 列时识别 ST；AKShare 接口常见返回为中文列名。接口异常或列名不匹配时，当前实现把所有股票标为非 ST。这会直接破坏历史股票池过滤。

修复要求：

- 显式支持真实接口列名并进行 schema 校验。
- ST 接口不可用或 schema 变化时标记状态为 `unknown`，不得默认为 `normal`。
- 增加中文列名、接口异常和 schema 变化测试。

### G1-03 证券状态区间被人为制造且不可复现

AKShare 主数据标准化把运行当天写入 `status_valid_from`。这不是 ST 状态真实生效日，也使相同原始输入在不同日期产生不同 curated 主数据，违反“不伪造状态历史”和确定性要求。现有复现测试只覆盖日行情，没有覆盖证券主数据。

修复要求：

- 未知状态起始日保持空值，并将 schema 调整为可空；另设 `observed_at` 表达快照观察时间，或使用原始抓取时间但不得称为状态生效日。
- 为证券主数据增加跨日期可复现测试和内容哈希测试。

### G1-04 BaoStock 错误码与登录结果未校验

登录、日线查询、证券主数据和交易日历查询均未检查 SDK `error_code/error_msg`。服务端错误会被转换为空表，CLI `fetch` 仍可能打印“抓取 0 行”并返回成功，无法阻止下游。

修复要求：

- 校验登录及每次查询错误码，失败时抛出带数据源、请求范围和错误码的异常。
- 空结果必须区分“合法无数据”和“请求失败”；请求失败返回非零退出码。
- 增加登录失败、查询失败和中途迭代失败测试。

### G1-05 缺失交易日检查无法发现首尾截断

预期区间由实际数据的最小/最大日期推导，因此请求区间开头或结尾整段缺失时不会报警；检查也未结合清单中的请求范围、上市日和退市日。这会让不完整下载被误认为完整覆盖。

修复要求：

- 质量检查显式接收请求起止日期，并结合交易日历及上市/退市边界计算预期日期。
- 覆盖报告按请求范围计算覆盖率，增加首段缺失、尾段缺失、上市前和退市后测试。

## 非阻断但必须修复

- `fetch` 未实现配置声明的重试次数和 AKShare→BaoStock 自动回退，也未生成原始抓取清单。
- 提供器测试覆盖不足，当前大量真实 SDK 错误分支未覆盖。
- `adjustment_factor` 在 raw close 为 0/空值时返回 1.0，会掩盖坏数据；应保留缺失并由质量检查阻断。
- 当前报告中的 `code_commit=no-git` 仅表示尚无提交，不代表 Git 不可用。
