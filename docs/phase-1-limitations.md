# Phase 1 数据层已知缺口与限制

本文档如实记录 Phase 1 数据层在免费数据源、退市/ST 历史、复权数据等方面的已知缺口。
本系统不伪造或静默填充缺失数据；缺口在数据与报告中明确标记。

## 1. 运行环境限制

- **GitHub remote 未配置**：本机 Git 可用，但仓库暂未配置 GitHub remote，因此当前只能完成本地分支和提交，不能推送或创建 Pull Request。不得自行猜测远程地址。
- **Python 版本**：项目声明 `requires-python = ">=3.11"`。当前 `.venv` 使用 Python 3.11.9，测试在 3.11 下全部通过。

## 2. 数据源覆盖缺口（幸存者偏差相关）

避免幸存者偏差要求保留上市、退市、停牌、名称与 ST 状态历史。免费数据源存在以下缺口：

### 2.1 退市股票历史

- **AKShare**：`stock_info_a_code_name` 仅返回当前在市股票列表，**不包含已退市股票**。直接使用该列表会引入幸存者偏差。
- **BaoStock**：`query_stock_basic` 的 `status` 字段可标识退市（`0`）并提供 `ipoDate`/`ouDate`，对退市股票覆盖较好，作为退市数据的主要来源。
- **缺口标记**：当主数据源（AKShare）无法提供退市股票时，应切换或补充 BaoStock。本系统在证券主数据中保留 `delist_date` 字段；缺失时为空，不伪造。

### 2.2 ST 状态历史区间

- **AKShare**：`stock_zh_a_st_em` 仅返回**当前** ST 股票快照，不提供历史 ST 状态区间。
- **BaoStock**：同样不提供完整的历史 ST 状态变更序列。
- **缺口标记**：证券主数据 schema 支持 `st_status` + `status_valid_from`/`status_valid_to` 多行区间历史（见 `make_st_interval_master` 样本），但免费数据源无法完整填充历史区间。这是已知缺口，需在后续阶段通过历史公告或付费数据源补全。G1-03 修复后，AKShare 快照中 `status_valid_from` 保持空值（不伪造生效日），另设 `observed_at` 记录快照观察时间。

### 2.3 停牌信息

- 免费数据源不提供显式的逐日停牌标记。本系统采用**保守推断**：成交量为 0 视为停牌（`is_suspended = (volume == 0)`）。这可能与真实停牌状态存在偏差（例如零成交但未停牌的情形）。

## 3. 复权数据缺口

- **复权因子**：本系统通过 `adjustment_factor = close_qfq / close_raw` 近似计算复权因子，而非数据源提供的精确因子。该比值在除权除息日会跳变，质量检查的 `adjustment_factor_continuity` 规则用相邻比值阈值检测异常跳变，但**无法区分真实的除权除息与数据错误**，可能产生误报。
- **前复权基准**：前复权价格以最新交易日为基准向前调整，历史 qfq 价格会随新的除权事件变化，因此 qfq 数据**不具有跨抓取时间的稳定性**。复现性测试基于同一份原始输入，不跨抓取时间比较 qfq。

## 4. 跨源差异

- AKShare 与 BaoStock 在收盘价、成交量上存在固有差异（数据源口径、复权方式不同）。`cross_source` 检查使用相对容忍度（默认收盘价 2%、成交量 10%，可在 YAML 配置）。超阈值记为 warning，不阻止下游。

## 5. 测试与复现性

- 所有单元测试离线运行，不调用 AKShare/BaoStock 公网接口；提供器通过子类化 mock `_call_*` 方法测试。
- `fetched_at` 和 `observed_at` 为非确定字段，内容哈希计算时排除（见 `config.manifest.content_hash_exclude_fields`），保证相同输入产生稳定哈希。
- 合成样本为虚构数据，仅用于测试 schema 与质量检查逻辑，不代表真实行情。
